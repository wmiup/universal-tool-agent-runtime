# 第 1 节课后作业

## 作业目标

通过边界设计和运行时校验，确认你理解“模型负责提议，Runtime 负责决策和执行”的核心原则。

## 课程—作业映射

| 作业编号 | 对应课程章节 | 作业要求 |
| --- | --- | --- |
| A1 | `lesson.md` 第 3–6 节 | 解释 Agent 边界，并画出 Model Gateway、Runtime、Tool Executor 的信任边界。 |
| A2 | `lesson.md` 第 7–10 节 | 完善模型决策校验，补充对应测试，并说明不可信输入和停止条件。 |
| A3 | `lesson.md` 第 5、8、10 节和安全检查卡 | 设计安全的公共运行事件，并验证事件和代码不会泄露敏感信息或执行不可信代码。 |

每个作业要求都必须能在课程内容中找到完整介绍。本节作业不引入课程没有讲过的新 API、库、模式或安全概念。

## A1：解释 Agent 边界并画出信任边界

画出下面三个模块的关系：

```text
Model Gateway
Agent Runtime
Tool Executor
```

在图中标注：

- 谁负责决策
- 谁负责执行
- 谁负责权限
- 谁负责状态
- 哪些数据需要验证

在 `answer.md` 中用自己的话回答：

- Agent 和 Chatbot 的核心区别是什么？
- Agent 和固定 Workflow 的核心区别是什么？
- 为什么模型只能提出工具调用建议，不能直接执行工具？
- `run.started`、`model.decision` 和 `run.completed` 分别在什么时机触发，主要供谁使用？
- 为什么公共事件是给 UI、日志和监控消费的观察钩子，而不是模型的决策输入？
- Agent 至少需要哪些停止条件？请至少列出三个，并说明它们防止什么问题。

## A2：完善模型决策校验并补充测试

修改 `implementation/lesson-one-runtime.ts` 中的决策校验，保留已有测试，并额外检查：

- 工具调用必须有 1–128 个字符的字符串 `id`。
- 工具名称必须是 1–100 个字符的字符串。
- 工具调用数组不能超过 8 个。
- `arguments` 不能是 `undefined`，并且必须是对象或数组。
- 工具调用数组中的每个工具调用必须是对象，不能是数组或 `null`。
- 使用 `unknown` 表示尚未校验的工具参数，并维护 `ModelDecision` 联合类型的边界。

为每条新增校验规则至少增加一个测试。测试必须覆盖正常输入和非法输入，并且不依赖真实模型供应商或真实工具。运行 `npm test`，在 `answer.md` 中记录结果。

## A3：设计安全的公共运行事件

设计以下事件：

```text
run.started
model.decision
run.completed
```

本节只要求设计当前 Runtime 可以产生的运行生命周期事件，不要求实现 Tool Executor、完整 Agent Loop 或工具执行事件。

事件必须满足：

- 不包含 API Key、Token 或 Cookie。
- 不包含模型隐藏思维过程。
- 不默认记录完整用户输入、完整工具参数或原始敏感上下文。
- 能够被 React UI、日志和监控消费。
- 字段类型可以用 TypeScript 表达。

在 `answer.md` 中说明每个事件的字段、触发时机和用途，并解释为什么这些字段不会把敏感数据或模型隐藏思维过程暴露给事件消费者。
